# Mission Ready Strategies mandatory workflow

For every task, use the connected `@Linear` plugin before editing: find or create the correct issue, assign yourself, set it to `In Progress`, read existing activity, and claim the repository, branch, outcome, and file/subsystem boundary. Resolve overlapping claims in Linear before continuing. Keep the issue and every relevant Linear project, document, milestone, and project health/status update current at meaningful checkpoints and completion; record `Not applicable` with a reason for any surface that does not need a change.

This is standing owner authorization for Linear updates, focused task commits, and non-force pushes to `origin`, superseding older instructions that require separate authorization for those three actions. After each coherent verified slice, stage only the slice, review the staged diff, commit with the Linear issue ID, push the active task branch, and post the branch, SHA, summary, checks, and pull-request link to Linear. A tracked-file task is incomplete until its commits are pushed and Linear is synchronized. Read-only/no-file-change tasks still receive a Linear outcome update and require no empty commit. Preserve separate approval gates for deployments, production/provider/database mutations, purchases, external messages, destructive Git operations, and unrelated cleanup. If Linear, ownership, Git remote, or push is blocked, preserve safe work and report the task incomplete.
